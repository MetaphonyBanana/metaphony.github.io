# Axis Universe

## 構成

```
index.html              エントリーポイント(canvas用の最小限のDOMのみ)
css/style.css            画面UIのスタイル
js/main.js                各モジュールを組み立てる起点
js/config.js               定数・チューニングパラメータ
js/sceneSetup.js            renderer/camera/composer/環境光などの初期化
js/stars.js                  星空(球殻分布+瞬き)
js/sagittarius.js             射手座(ティーポット型アステリズム)
js/introActors.js              矢(オープニング演出用)
js/banana.js                    ガラスのバナナ+破片の読み込み・破砕
js/axes.js                       三軸(X/Y/Z)+Xの刃跡トレイル
js/axisCamera.js                  軸クリック時の「カメラステーション」計算+遷移アニメーション
js/hotspots.js                     星に紐づくセリフのデータ・メッシュ
js/dialogue.js                      セリフの浮遊表示(星への投影)
js/introSequence.js                  オープニング演出タイムライン+状態管理
js/data/axisContent.js                各軸ページの内容データ(タイトル・遷移先URLなど)
```

`banana.glb` を使う場合は `index.html` と同じ階層に置いてください(無ければ自動でプレースホルダー形状になります)。

## ローカルでの実行方法

ES Modules(`import`/`export`)と `GLTFLoader` の `fetch` は、`file://` で直接HTMLを開くとブラウザのCORS制限に引っかかって動かないことがあります。プロジェクトルートで簡易サーバーを立ててから開いてください。

```bash
# 例: Python
python3 -m http.server 8000
# → http://localhost:8000/ を開く
```

## 現状の状態(2026-08-06時点)

- オープニング演出(射手座→矢→破砕→三軸出現)は移植済み、動作は元の単一HTML版と同一です
- `js/data/axisContent.js` に、Y軸=Nine Stories(原点=A Perfect Day for Bananafish / 先端=Teddy)、X軸=軸ラベル無しの2点構成、Z軸=Yと同じ3点構成(内容未定)、という内容を反映済み
- **home(操作可能)時のデフォルトカメラ**を、原点から対角(1,1,1)方向に配置(`config.js`の`HOME_CAMERA_POS`)。3軸が幾何学的に必ず120度ずつ開いて見える位置で、オープニング演出の最後(Z軸が伸びる間)にそこへ滑らかに移動する
- **軸クリック時のカメラ演出**を全面的に作り直した(`js/axisCamera.js`)。以前は軸ごとに`sideDir = cross(軸方向, up)`で位置を計算していたため、外積の符号が軸によって反転し「X軸だけホームの反対側に飛ぶ」ズレが発生していた
  - **新方式**: ホーム位置(`HOME_CAMERA_POS`、(1,1,1)方向)から軸方向の成分だけを取り除いた「軸に直交する残りの方向」を station 位置として使う。ホーム位置は3軸に対して完全に対称なので、これで導出すればX/Y/Zどの軸でも原点からの距離・見た目の「感じ」が自動的に揃う(実際、X/Y/Z stationは互いに座標を入れ替えただけの位置になる)
  - **遷移の動き**: 原点からの距離(半径)を保ったまま、序盤〜中盤は原点を向いたまま球面上を回転し(「位置は固定されたまま軸がぐるっと回る」ように見える)、終盤(smoothstepで滑らか)で注視点だけ原点→軸の中点へ、upだけworld+Y→軸専用upへ寄せて「軸の中点と直交する視点」に着地する
  - **回転方向**: 常に最短経路で回すようにした(=どの軸へ行くときも90度以内で回る)。ホーム位置(1,1,1)の対称性上、X軸への遷移とY軸への遷移は互いに鏡写しの逆回転になる(X:+45度, Y:-45度, Z:0度=水平回転なし、高さだけ変化)。もし常に同じ回転方向(時計回り/反時計回り)を強制すると、その裏返しの軸だけ大回り(最大315度)になってしまうため、「毎回同じ方向」ではなく「毎回同じ、短くて自然な回転」を優先している。⚠️ 実際に見て特定の軸の回り方に違和感があれば、この方針(最短経路)自体を`axisCamera.js`の`dTheta`計算部分で調整可能
  - `config.js`の`AXIS_STATION`から`distance`/`elevation`は不要になったため削除し、`duration`のみ残した
- **クリック判定の当たり判定シリンダー**を追加(`js/axes.js`の`makeHitCylinder`)。見た目の細い線(1px)ではなくraycast専用の太い透明円柱を各軸に重ね、`axisHitAreas`配列としてmain.jsのクリック処理が参照する。⚠️ `axisHitAreas`は`axes.js`側の変更点なので、`main.js`だけ差し替えて`axes.js`を古いまま残すと「`axes.axisHitAreas`がundefined」で軸クリックが反応しなくなる(実際に一度発生した不具合)。ファイル差し替えは常にプロジェクト全体を丸ごと行うのが安全
- **Z軸のガウス波束らせん**を実装(`js/zAxisWave.js`)。ユーザー提供の参考HTML(Three.js r128のスタンドアロン実装)の式をそのまま移植:
  Ψ(x,t) = exp(-(x-v_g t)²/2σ²)·exp(i k0(x-v_p t))、ω0=ħk0²/(2m)、v_p=ω0/k0(位相速度)、v_g=ħk0/m(群速度)。
  パラメータは固定(調整UIなし): k0=3, σ=3, m=1, speed=1, ħ=1。projections(Re/Im平面への投影線)は表示せず、複素螺旋(フルヘリックス)のみ描画
  - 実部・虚部は軸に直交する2方向(実部=world+X, 虚部=world+Z)へ展開、xは軸方向(world+Y)にそのままワールド座標として使う(参考HTMLのx軸と1:1)
  - 包絡線(振幅)は群速度v_gで、位相(らせんの巻き)は位相速度v_pで、それぞれ異なる速さで並進する(自由粒子の分散関係ではv_g=2v_pになるため、波束の中を位相がすり抜けていくように見える)。これが参考HTMLの動きの本体
  - 軸の外(原点の手前・先端の先、振幅がほぼ0になる領域)まで並進範囲にマージンを取ってループさせているので、境界の「ジャンプ」は見えない。1周 約12秒
  - 演出の順序: Z軸クリック→カメラが軸ステーションへ完全に到達してから(`flyToAxisStation`の`onComplete`)、`reveal(t)`でフェードイン。表示開始のタイミングを波束のt=0として、原点の手前から流れ始める
  - 位相を色相(HSL hue)にマッピングし、振幅が小さくなるほど暗くフェードする色付けは元HTMLには無い、このシーン独自の演出(既存のpale-blue+bloomの世界観に合わせた)
  - X/Y軸クリック時は`reset()`で非表示に戻し、次にZ軸へ戻ったときまた最初から流れるようにしてある
- **三軸(X/Y/Z)のラベル**を実装(`js/axisLabels.js`)。各軸の先端よりわずか手前にCanvasテクスチャのSprite(常にカメラを向くので、どの角度から見ても文字として読める)を配置。intro演出が終わりhome状態になったタイミングで`main.js`側が`axisLabels.show()`を呼んで表示する
- Z軸の位相回転更新(`zWave.update`)は`main.js`のレンダーループでtry/catchして隔離してある。ここで例外が起きてもレンダーループ自体が止まらない(=軸が反応しなくなったように見える事態を避ける)ようにするための安全策。もし軸クリックが反応しない場合はブラウザのコンソール(F12)に赤いエラーが出ていないか確認してほしい
